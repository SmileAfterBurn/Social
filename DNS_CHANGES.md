# DNS — пропозиція змін для підключення до Firebase Hosting

**Домен:** соціальна-мапа-турботи.in.ua  
**Punycode:** `xn-----6kcabai0duamijkkre2adp2c4htj.in.ua`

---

## 1) Поточний експорт зони (те, що ви надали)

```
;;	
;;	Domain:    соціальна-мапа-турботи.in.ua
;; 	Exported:  2026-02-09 22:44:25
;;
$ORIGIN соціальна-мапа-турботи.in.ua
$TTL 900
@	IN	A	91.206.200.52
www	IN	A	91.206.200.52
*	IN	A	91.206.200.52
@	IN	MX	0 mx.services.
@	IN	TXT	v=spf1 include:_spf.ukraine.com.ua ~all
```

> Висновок: наразі `@`, `www` і `*` вказують на IP `91.206.200.52`.

---

## 2) Короткі кроки для підключення до Firebase Hosting
1. Увійдіть у **Firebase Console → Hosting** → виберіть проект з сайтом `social-map-of-care`.
2. Натисніть **Add custom domain** і введіть `соціальна-мапа-турботи.in.ua` (або punycode `xn-----6kcabai0duamijkkre2adp2c4htj.in.ua`).
3. Firebase покаже **TXT record** для верифікації та набір A/CNAME записів, які потрібно додати — **скопіюйте їх**.
4. В панелі реєстратора (DNS) додайте: 1) TXT верифікацію, 2) A / CNAME записи від Firebase.
5. Дочекайтесь підтвердження у Firebase та випуску SSL (зазвичай до 24 годин).
6. Після успішної перевірки можна видалити старі A-записи (`91.206.200.52`) якщо вони більше не потрібні.

---

## 3) Приклад (зразок) записів — **завжди** використовуйте ті значення, які надасть Firebase Console

```
# приклад (зразок)
@	IN	A	199.36.158.100
www	IN	CNAME	ghs.googlehosted.com.
*	IN	A	199.36.158.100   ; опціонально (wildcard)
@	IN	TXT	"v=spf1 include:_spf.ukraine.com.ua ~all"
@	IN	TXT	"firebase=YOUR_VERIFICATION_TOKEN"
```

> Примітка: IP `199.36.158.100` і `ghs.googlehosted.com` — приклади; **перед застосуванням** використайте записи, що згенерував Firebase.

---

## 4) Перевірки (команди)
- `dig +short A соціальна-мапа-турботи.in.ua`
- `dig +short A www.соціальна-мапа-турботи.in.ua`
- `dig +short TXT соціальна-мапа-турботи.in.ua`
- `curl -I https://соціальна-мапа-турботи.in.ua` (HTTP headers, перевірка SSL)

## 5) Варіанти роботи — оберіть, будь ласка

- **A)** Я згенерую готовий файл з оновленими записами для **Vercel** (або Firebase) — ви вставите їх у панель реєстратора (рекомендовано, якщо ви керуєте DNS самостійно).
- **B)** Я внесу DNS-записи самостійно (потрібен тимчасовий доступ або API-токен реєстратора).
- **C)** Ви додасте домен у Vercel (або Firebase) і вставите сюди TXT verification token — я перевірю верифікацію і підкажу/застосую остаточні записи.
- **D)** Допоможу налаштувати автоматичний деплой на Vercel (налаштування GitHub Secret `VERCEL_TOKEN` або підключення репозиторію у Vercel Dashboard).

---

Якщо оберете B — надішліть доступ (тимчасові облікові дані або інструкцію з API/панеллю). Якщо оберете C — вставте сюди TXT verification token, який покаже Vercel або Firebase після додавання домену, і я перевірю статус верифікації.

---

## 6) Vercel — приклад записів (шаблон)
(Перед застосуванням **завжди** використовуйте ті значення, які згенерував Vercel Dashboard)

```
# приклад Vercel — для apex + www + wildcard
@   IN  A       76.76.21.21
www IN  CNAME   cname.vercel-dns.com.
*   IN  CNAME   cname.vercel-dns.com.   ; опціонально (wildcard)
@   IN  TXT     "v=spf1 include:_spf.ukraine.com.ua ~all"  ; збережіть існуючий SPF
```

> Примітка: IP `76.76.21.21` і `cname.vercel-dns.com` — приклади; **перед застосуванням** використайте записи, що згенерував Vercel.
